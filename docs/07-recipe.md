# レシピ仕様

1つのレシピは「材料の配置・完成品・照合モード・コスト・条件・報酬」で構成し、色（ステーション）ごとに複数持てる。

| 項目         | 選択肢・内容                                                     | 入力する画面 |
| ------------ | ---------------------------------------------------------------- | ------------ |
| 材料・完成品 | 実物のアイテム（完成品は個数も含む）                             | エディタ     |
| 形状         | 固定（配置どおり、上下左右の平行移動は許す）／不定（数だけ一致） | CustomForm   |
| 照合モード   | ID のみ／＋名前／＋説明文／完全一致                              | CustomForm   |
| コスト       | 経験値レベル、スコアボード（例：`money` を 100）                 | CustomForm   |
| 条件         | 必要なタグ（例：`quest_2_clear`）、1人1回まで                    | CustomForm   |
| 報酬         | クラフト時に実行するコマンド（例：`function quest/stage3`）      | CustomForm   |

## 照合の実装

- 完全一致は `ItemStack.isStackableWith` を使う。種類・カスタムデータ・プロパティをまとめて比較できる
- ただしスタックできないアイテム（剣・防具など）では常に false を返す。この場合は `typeId`・`nameTag`・説明文・エンチャント・耐久値・ダイナミックプロパティを自前で比較する
- 同じ配置に複数のレシピが当てはまる場合は、照合が厳しい方を優先する（名前付きの鍵レシピが、普通のレシピに食われないように）
- 不定形は、レシピの材料それぞれに置かれたアイテムを重複なく1つずつ割り当てられるかで判定する。照合モードが緩いと1つのアイテムが複数の材料に当てはまるため、割り当てを試し直す
- 照合の厳しさが同じなら、配置まで指定している固定形状の方を優先する

## コスト・条件・報酬の実装

- 材料が当てはまっても、条件（タグ・1人1回）やコスト（経験値レベル・スコア）を満たさなければ完成品スロットは空のままにし、理由をチャットで1回だけ伝える
- 完成品を取られたときにもう一度確かめてから、材料の消費・コストの支払い・1人1回の記録・報酬コマンドの実行をまとめて行う
- 1人1回の記録はプレイヤーのダイナミックプロパティ `craft:done.<recipeId>` に残す
- 報酬コマンドはクラフトしたプレイヤーとして `runCommand` で実行する。先頭の `/` は取り除く
- スコアボードの目的が見つからないレシピは作れないものとして扱い、コンテンツログに警告を出す
