# データ保存

アイテムは JSON にせず、「ストラクチャー＋保管用エンティティ」で NBT ごと保存する。ItemStack には文字列化する API がないため。すべてワールドに保存されるので、`.mcworld` を配布すればレシピも一緒に届く。

| データ                         | 置き場所                                                                            |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| ステーションの識別             | ブロックの種類（色）                                                                |
| 色ごとの設定・レシピのメタ情報 | ワールドのダイナミックプロパティ（色をキーにした JSON。アイテムのデータは含めない） |
| 材料・完成品のアイテム         | ストラクチャー `craft:r_<recipeId>`（保管用エンティティのインベントリ）             |
| 作業中のグリッドの中身         | プレイヤーごとに退避（方式はアイテムと同じ）                                        |

## 保存（エディタで保存したとき）

1. 管理者の近く（チャンクが読み込まれている場所）に、透明な保管用エンティティ `craft:recipe_store`（`minecraft:inventory` 持ち）を召喚する
2. 材料と完成品を `setItem` で入れる
3. `structureManager.createFromWorld("craft:r_<recipeId>", dim, pos, pos, { includeBlocks: false, includeEntities: true, saveMode: World })` で保存する
4. エンティティを `remove()` で消す（kill にしない＝中身をドロップさせない）

## 読み込み（ワールド起動後、最初のプレイヤーが参加したとき）

1. `place(..., { includeBlocks: false, includeEntities: true })` で配置する
2. エンティティのアイテムを `clone()` してメモリにキャッシュする
3. エンティティを消す。以降はキャッシュだけを使う

## 退出・シャットダウン対策

`system.beforeEvents.shutdown` は制限付きモードで呼ばれ、コンテナのアイテムを読むこともストラクチャーを作ることもできない（実機でも、画面を開いたまま `/reload` やサーバー停止をするとグリッドのアイテムは消えた）。そこで、閉じたときに退避するのではなく、開いている間ずっと保存しておく。

1. 画面の中身が変わるたびに（1 tick 分の操作をまとめた後で）、守るスロットの中身をストラクチャー `craft:p_<playerId>` に保存する。空になったら消す
2. 正常に閉じてプレイヤーに中身を返したら、ストラクチャーを消す
3. 退出・シャットダウンで閉じたときは残る。次に参加したときに返して消す

守るスロットはクラフト画面ではグリッド（完成品スロットは未クラフトなので含めない）、エディタではグリッドと完成品。

保存は操作の次の tick なので、その間に落ちると保存が1つ前の状態になる。グリッドから取り出した直後なら取り出した分が二重に返り、入れた直後なら入れた分が消える。1 tick の間に限られるので許容する。
